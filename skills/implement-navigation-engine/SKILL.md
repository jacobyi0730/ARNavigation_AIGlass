# 내비게이션 엔진 구현

## 불변 규칙

- 안내 순서는 시작점, 경유지 추가 순서, 목적지다.
- 목적지는 하나만 존재하고 재지정 시 교체한다.
- 완료된 지점은 다시 안내 대상으로 선택하지 않는다.
- 지도 편집 draft와 확정 세션을 분리하고 취소 시 원본을 복원한다.
- 초기 도착 기준은 반경 10 m 안에서 3초 연속 유지다.
- 오래되거나 정확도 기준을 넘은 위치는 도착 판정에 사용하지 않는다.
- 각도 계산은 0°/360° 경계를 안전하게 처리한다.

## 작업 절차

1. 배정된 `docs/tasks/stage-XX.md` 작업 ID와 관련 기획서 절만 읽는다.
2. UI와 Android SDK 타입에 의존하지 않는 도메인 계약을 먼저 정의한다.
3. `LocationRepository`와 `OrientationRepository`는 인터페이스, 실제 구현, Fake를 분리한다.
4. 거리, 절대 방위각, 상대각, 도착 유지 시간과 상태 전이를 작은 순수 함수로 구현한다.
5. 시간 의존 로직에는 주입 가능한 clock/time provider를 사용한다.
6. StateFlow는 단일 상태 소유자에서 갱신하고 같은 위치 샘플의 중복 도착 처리를 막는다.

## 필수 테스트

- 목적지 교체, 경유지 추가·삭제·재정렬, draft 취소
- 정상·비정상 상태 전이와 사용자 종료
- 경유지 0개/1개/여러 개의 전체 안내 순서
- 동일 좌표, 날짜 변경선, 359°↔1° 각도 경계
- 도착 반경 진입·이탈, 3초 유지, GPS 튐과 중복 샘플
- 오래된 위치, 낮은 정확도, 센서 품질 저하와 회복

테스트가 통과한 뒤 공개 계약 변경과 UI 작업자에게 필요한 샘플 상태를 인계한다. 실패 또는 비직관적 계산 규칙은 `$record-retrospective`로 기록한다.
