# 프로젝트 회고 기록

## 기록 판단

다음 중 하나이면 기록한다.

- 명령, 빌드, 테스트, 도구 또는 실기기 검증이 실패했다.
- 문서나 코드의 가정이 실제 환경과 달랐다.
- 같은 문제의 재발 가능성이 있다.
- 이후 에이전트의 설계나 작업 순서를 바꿀 제약·결정·학습이 생겼다.
- 임시 우회가 남았거나 후속 작업이 필요하다.

단순 오타를 즉시 고쳤고 재사용할 교훈이 없으면 기록하지 않는다.

## 작성 절차

1. `docs/Retrospective.md`를 전부 읽고 같은 사건이나 교훈이 있는지 찾는다.
2. 중복이면 기존 항목의 증거, 해결, 후속 조치만 갱신한다.
3. 새 항목이면 `RET-YYYY-MM-DD-NNN` ID를 부여하고 문서 템플릿을 따른다.
4. 관찰된 사실과 추론을 구분한다. 명령, 오류 핵심 문구, 관련 경로 등 재현 가능한 증거를 남긴다.
5. 근본 원인, 실제 해결, 재발 방지 규칙과 담당 가능한 후속 조치를 기록한다.
6. 새 작업이 필요하면 해당 `docs/tasks/stage-XX.md`에 새 작업 ID로 추가하거나 연결한다.

## 작성 규칙

- 비난 없이 시스템, 계약, 검증 절차와 기술 원인에 집중한다.
- API 키, 정밀 위치, 개인정보, 인증서 비밀값을 기록하지 않는다.
- 전체 로그를 붙이지 말고 핵심 오류와 재현 명령만 남긴다.
- 미확인 원인은 `추정`으로 표시하고 확인 전까지 사실처럼 쓰지 않는다.
- 해결되지 않은 항목은 상태를 `Open` 또는 `Monitoring`으로 두고 후속 조치를 체크하지 않는다.
- 해결과 재현 방지 검증이 끝난 경우에만 `Resolved`로 표시한다.
