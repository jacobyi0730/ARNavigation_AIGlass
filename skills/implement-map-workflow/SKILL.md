# 지도 워크플로 구현

## 준비

1. `docs/tasks/stage-08.md`의 배정 작업 ID와 기획서 5.2절만 읽는다.
2. `NavigationUiState`, 지도 이벤트, 확정 세션 계약을 확인한다. 계약이 없으면 임의 타입을 만들지 말고 먼저 합의한다.
3. Maps API 키를 출력하지 않고 설정 존재 여부만 확인한다.

## 구현 규칙

- `MapScreen(state, onEvent)`와 지도 SDK 연결 영역을 분리해 UI 테스트 가능하게 한다.
- 첫 유효 위치에서만 카메라를 자동 이동하고 이후 사용자의 지도 조작을 방해하지 않는다.
- 편집 모드는 기본, 목적지, 경유지 중 하나만 활성화한다.
- 목적지는 항상 하나, 경유지는 추가 순서 번호를 유지한다.
- 마커 삭제·재정렬과 draft 취소는 ViewModel/도메인 이벤트로 요청한다.
- 진행 중 지도는 조회 전용으로 표시하고 편집 컨트롤을 노출하지 않는다.
- 지도 Composable이 위치 업데이트를 직접 소유하지 않게 한다.
- 시작 입력 검증은 목적지, 권한, 위치 서비스, 최신 위치와 정확도를 모두 반영한다.
- 마커는 색상 외에 아이콘, 번호, 설명으로 구분한다.

## 검증

- 목적지 생성과 교체
- 경유지 연속 추가, 중간 삭제, 번호 재정렬
- 목적지 없는 시작과 위치 준비 실패
- 취소 후 draft 폐기
- 진행 중 시작·완료 경유지·목적지 재표시
- AR로 복귀한 뒤 동일 세션 유지

가능한 로직은 Fake state 기반 Compose UI 테스트로 검증하고 실제 Maps 렌더링은 기기 테스트 절차를 남긴다. 지도 SDK 제약이나 실패는 `$record-retrospective`로 기록한다.
