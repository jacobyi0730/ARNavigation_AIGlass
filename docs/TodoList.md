# ARNavigation 구현 TodoList

## 1. 문서 목적

이 문서는 [AR 내비게이션 앱 기획서](./AR_내비게이션_앱_기획서.md)를 `ARNavigation` Android 프로젝트에 구현하기 위한 작업 체크리스트다. 작업은 기능 단위와 선행관계에 따라 정렬했으며, 각 단계의 완료 조건을 충족한 뒤 다음 통합 단계로 넘어간다.

### 현재 프로젝트 기준선

- [x] `ARNavigation` 단일 `app` 모듈 프로젝트 생성
- [x] Kotlin/Jetpack Compose/Material 3 기본 설정
- [x] 패키지 및 application ID `com.wjs.arnav` 설정
- [x] `minSdk 31`, `targetSdk 37`, `compileSdk 37` 설정
- [x] 기본 단위 테스트 태스크 실행 확인 (`testDebugUnitTest`, 2026-08-12 성공)
- [ ] 기본 템플릿의 `Greeting` UI와 예제 테스트를 실제 앱 구조로 교체

> 현재는 기본 Compose 템플릿 상태다. Google 지도, 위치, 화면 전환, ViewModel, ARCore 및 3D 렌더링 관련 의존성은 아직 구성되지 않았다.

## 2. 구현 원칙과 MVP 확정 범위

### 2.1 기본 구현 원칙

- [ ] Single Activity + Jetpack Compose 기반으로 구성한다.
- [ ] UI는 단방향 데이터 흐름을 사용하고, Composable에 위치·센서·AR 비즈니스 로직을 직접 넣지 않는다.
- [ ] `ViewModel`이 화면 상태와 사용자 이벤트를 관리하고 위치/방향/세션 기능은 인터페이스로 분리한다.
- [ ] 지도 편집 상태와 확정된 길찾기 세션을 분리해 `취소` 시 편집 내용만 폐기할 수 있게 한다.
- [ ] GPS 및 센서의 원시 Android 타입을 도메인 계층에 노출하지 않는다.
- [ ] 위치 좌표와 API 키 등 민감정보를 로그 또는 Git 저장소에 남기지 않는다.
- [ ] 실제 기기가 필요한 기능과 JVM에서 검증 가능한 순수 로직을 분리한다.

### 2.2 MVP 정책

- [x] 실제 보행로 탐색이 아닌 사용자가 지정한 좌표의 직선 순서 안내로 정의
- [x] 경유지는 지도에 추가한 순서대로 안내
- [x] 진행 중 경로 편집은 허용하지 않고 지도 조회만 허용
- [x] 도착 반경 초기값 10 m, 반경 내 유지 시간 3초 적용
- [x] 위치 정확도 경고 기준 초기값 25 m 적용
- [ ] AR 평면 미인식 시 2D 보조 화살표 포함 여부 최종 확정 (`Should`, 기본안: 포함)
- [ ] 앱 강제 종료 후 진행 세션 복원 포함 여부 최종 확정 (`Could`, 기본안: MVP 제외)
- [ ] ARCore 미지원 기기의 지도 전용 모드 제공 여부 최종 확정 (기본안: 지원 불가 안내 후 종료)

## 4.2 단계 2: 도메인 모델 및 세션 상태 관리

### 2.1 도메인 모델

- [ ] `GeoPoint(latitude, longitude)` 값 객체를 구현하고 좌표 범위를 검증한다.
- [ ] `NavigationPoint`와 `PointType(START, WAYPOINT, DESTINATION)`을 구현한다.
- [ ] `ArrivalStatus(PENDING, ARRIVED, SKIPPED)`를 구현한다.
- [ ] `NavigationStatus(IDLE, EDITING, NAVIGATING, PAUSED_QUALITY, ARRIVED)`를 구현한다.
- [ ] `NavigationSession`을 불변 데이터 모델로 구현한다.
- [ ] 도착 반경, 유지 시간, 위치 품질 기준을 `NavigationConfig`로 분리한다.

### 2.2 지도 편집 상태

- [ ] `MapEditMode(DEFAULT, DESTINATION, WAYPOINT)`를 구현한다.
- [ ] 확정 데이터와 편집용 draft 데이터를 분리한다.
- [ ] 목적지 지정 시 기존 목적지가 하나만 유지되도록 한다.
- [ ] 경유지를 추가 순서대로 저장하고 화면용 순번을 계산한다.
- [ ] 경유지 삭제 후 남은 순서를 재정렬한다.
- [ ] 최소 거리 이내 중복 경유지를 거부하는 정책을 구현한다.
- [ ] 편집 완료/취소 이벤트를 구현하고 취소 시 원본 세션을 복원한다.

### 2.3 세션 상태 머신

- [ ] `IDLE → EDITING → NAVIGATING → ARRIVED → IDLE` 정상 전이를 구현한다.
- [ ] 센서 품질 저하에 따른 `NAVIGATING ↔ PAUSED_QUALITY` 전이를 구현한다.
- [ ] 잘못된 상태 전이를 거부하거나 명시적 오류로 처리한다.
- [ ] 시작 시 최신 유효 위치를 시작점으로 고정한다.
- [ ] 진행 중 지도 조회에서는 세션을 수정할 수 없게 한다.
- [ ] 사용자 안내 종료 시 위치/센서/AR 리소스를 해제할 수 있는 종료 이벤트를 제공한다.

### 2.4 ViewModel 계약

- [ ] 화면에서 사용할 단일 `NavigationUiState` 또는 화면별 파생 UiState를 정의한다.
- [ ] UI 이벤트와 일회성 효과(메시지, 화면 이동, 설정 열기)를 분리한다.
- [ ] `SavedStateHandle`로 최소 편집/화면 상태 복구 범위를 정의한다.

- [ ] 위치 수신 실패에 재시도와 설정 이동을 제공한다.
- [ ] GPS 정확도 저하 시 시작/안내 정책에 맞는 경고를 표시한다.
- [ ] 나침반 품질 저하 시 8자 보정 방법을 표시한다.
- [ ] 지도 로딩 실패 시 세션과 마커 데이터를 유지한 채 재시도한다.
- [ ] AR 추적/세션 오류 복구 후 안내가 중복 시작되지 않게 한다.
- [ ] 예외 메시지에 원인과 사용자가 취할 수 있는 조치를 함께 제공한다.

### 12.2 생명주기 및 상태 보존

- [ ] 화면 회전 또는 구성 변경 후 편집/안내 상태가 유지된다.
- [ ] 백그라운드 이동 시 카메라, AR, 위치, 센서를 안전하게 일시 중지한다.
- [ ] 복귀 시 새 위치·방향을 확보한 후 안내를 재개한다.
- [ ] 프로세스 복원 범위를 정책에 맞게 구현하고 오래된 센서값은 복원하지 않는다.
- [ ] 화면 이동과 앱 백그라운드 전환 반복 시 메모리/리소스 누수를 검사한다.

### 12.3 접근성 및 사용성

- [ ] 주요 버튼에 최소 48 dp 터치 영역을 제공한다.
- [ ] 지도 마커, 버튼, 상태 아이콘에 TalkBack 설명을 제공한다.
- [ ] 마커와 안내 지점은 색상 외에 번호/아이콘/텍스트로 구분한다.
- [ ] 카메라와 지도 위 텍스트에 야외 가독성을 위한 대비 배경을 적용한다.
- [ ] 글꼴 크기 확대 시 버튼과 상태 정보가 잘리거나 겹치지 않게 한다.
- [ ] 안전 문구가 핵심 방향 안내를 가리지 않는지 검증한다.

## 5. 멀티 에이전트 병렬 작업안

멀티 에이전트는 공통 계약이 확정된 뒤 서로 다른 파일 영역을 맡을 때 사용한다. 동일한 ViewModel, Version Catalog, Manifest, Navigation graph를 여러 에이전트가 동시에 수정하지 않는다.

### 병렬 구간 A: 기반 기능

단계 1과 도메인 인터페이스가 끝난 뒤 진행한다.

| 트랙 | 담당 기능 | 수정 권장 영역 | 필요 계약 |
|---|---|---|---|
| A | 도메인/세션 | `domain`, 세션 ViewModel/Store | 모델과 이벤트 정의 |
| B | 위치/권한 | `data/location`, 준비 상태 | `LocationSample`, 오류 타입 |
| C | 방향 센서 | `data/orientation` | `OrientationSample`, 품질 타입 |

- [ ] 시작 전 공유 데이터 타입과 인터페이스를 main 브랜치에 먼저 반영한다.
- [ ] 각 트랙은 자신의 Fake 구현과 단위 테스트를 함께 작성한다.
- [ ] 통합 담당자가 단계 6 전에 계약 변경과 충돌을 정리한다.

### 병렬 구간 B: 기능 화면

단계 7의 앱 셸과 공통 UiState 계약이 끝난 뒤 진행한다.

| 트랙 | 담당 기능 | 수정 권장 영역 | 주의사항 |
|---|---|---|---|
| D | 지도 화면 | `feature/map` | 공유 ViewModel 직접 변경 대신 합의된 이벤트 사용 |
| E | AR 세션/렌더러 | `feature/ar`의 렌더링 영역 | 실기기 검증 결과 포함 |
| F | 테스트/접근성 | fake, test, 공통 UI 검증 | 미완성 UI에 과도하게 결합하지 않음 |

- [ ] D와 E를 병렬 진행하되 화면 전환 계약은 단계 7 결과를 고정해 사용한다.
- [ ] 3D 모델 자산 담당자는 파일명, 축, 단위, 라이선스를 E 트랙에 전달한다.
- [ ] 지도와 AR 기능 완료 후 단일 통합 담당자가 단계 10~11을 수행한다.

### 병렬 작업 완료 기준

- [ ] 각 트랙이 수정한 파일 범위와 공개 계약 변경을 기록한다.
- [ ] 각 트랙의 빌드 및 관련 테스트가 독립적으로 통과한다.
- [ ] 임시 mock/fake와 TODO가 통합 시 누락되지 않도록 목록화한다.
- [ ] 통합 전 공통 파일 충돌을 먼저 해소하고 전체 회귀 테스트를 수행한다.

## 6. MVP 완료 정의(Definition of Done)

- [ ] 사용자가 현재 위치 중심 지도에서 목적지 한 개를 지정할 수 있다.
- [ ] 사용자가 복수 경유지를 순서대로 추가하고 개별 삭제할 수 있다.
- [ ] 취소 시 편집 내용이 반영되지 않고 AR 화면으로 복귀한다.
- [ ] 시작 시 현재 위치가 시작점으로 저장되고 AR 안내가 시작된다.
- [ ] AR 인디케이터가 인식된 바닥면에서 현재 안내 지점 방향을 가리킨다.
- [ ] 경유지를 추가 순서대로 도착 처리한 뒤 목적지로 안내한다.
- [ ] AR↔지도 전환 후에도 마커와 진행 상태가 유지된다.
- [ ] 권한, 위치, 방향 센서, AR 추적 품질 문제를 크래시 없이 안내한다.
- [ ] 화면 회전과 foreground/background 전환에서 세션과 리소스가 안전하게 유지된다.
- [ ] 핵심 단위/UI 테스트와 기획서의 인수 조건이 모두 통과한다.
- [ ] 지원 대상 실제 기기에서 30 FPS 목표와 야외 방향 안내를 검증한다.
- [ ] API 키, 개인정보, 라이선스 및 빌드 문서가 릴리스 기준을 충족한다.
